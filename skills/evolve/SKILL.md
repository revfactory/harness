# Harness Evolve

기존 하네스의 행동을 보존하면서 실행에서 얻은 교훈을 반영한다. 새 지침을 더하기 전에 기존 내용을 수정·통합·제거할 수 있는지 검토한다.

## 워크플로우

### Phase 1: 현재 구성과 실행 근거 수집

1. 프로젝트 지침·등록정보·런타임 로딩 설정에서 활성 에이전트·스킬·오케스트레이터·참조·이력의 정본과 소비자를 발견한다. 실제 경로를 확인해 별칭·사본을 중복 처리하지 않고, 무관한 구성은 편집 범위에서 제외한다.
2. 발견한 정의의 내용·변경 이력과 최근 실행 산출물을 읽는다. 새 피드백이 없어도 기존 내용은 검토한다. 이미 제공된 피드백은 다시 묻지 않는다.
3. 최초에는 범위 안의 내용을 전수 검토한다. 이후 전체 목록의 변화를 확인하고 변경·영향·미검토 영역과 오래 검토하지 않은 내용을 읽는다. 이전 판정은 내용과 근거가 유지될 때만 재사용하고 검토·미검토 범위를 보고한다.
4. 편집 전 상태와 보호할 행동을 기록한다. 반복 교정·재시도·수동 우회는 원본 실행에서 원인을 확인한다. 현재 등록정보를 복제한 수량·목록·파일 위치는 드리프트 후보로 표시한다.

### Phase 2: 기존 내용과 피드백 판정

같은 의미를 다루는 기존 규칙부터 찾고 적용 조건·예외·도입 이유·소비자를 대조한다.

| 조치 | 판정 근거 |
|---|---|
| 유지 | 현재 계약에 필요한 고유한 행동·예외 |
| 수정 | 기존 규칙의 모호함·잘못된 범위·사실 드리프트 |
| 통합 | 조건과 의무가 같은 사본이며 소비자가 정본에 도달함 |
| 조건부 참조 | 특정 분기에서만 필요한 유효한 상세 설명 |
| 제거 | 현재 근거로 폐기·대체·무관함을 확인한 내용 |
| 보류 | 필요성·영향·상충을 판정할 근거가 부족함 |

최근 미사용·문서의 나이·모델의 일반 지식은 단독 제거 근거가 아니다. 표현이 비슷해도 조건·책임이 다르면 보존한다. 기존 규칙의 실행 미준수는 전달·로딩 경로부터 점검한다. 후보가 없으면 무변경으로 마친다.

### Phase 3: 일반화와 최소 변경

1. 사례의 근본 원인을 여러 상황에 적용되는 원리로 정제하고 기존 문장을 대체한다. 기존 규칙으로 해결할 수 없는 새 필요에만 내용을 추가한다. 각 후보에 근거·조치·보호할 행동·검증을 연결한다.
2. 정본에 행동과 짧은 이유를 남긴다. 에이전트는 역할·입출력·협업 경계를 소유하고 스킬은 상세 절차를 소유한다. 소비자에는 필요한 연결을 남기고, 실제 전달 여부를 확인한다.
3. 현재 구성의 개수·파일명·경로를 지침에 고정해 복제하지 않는다. 구성과 위치는 소유한 등록정보·정본에서 발견한다. 유효한 포인터는 도달 조건과 함께 유지하며 이동·확장에도 발견되는지 검증한다.
4. 같은 논리적 변경의 정본과 소비자를 함께 수정한다. 파일 언어와 기존 범위를 유지한다. 상위 사용자 요구·승인·검증 경계를 보존하고, 과거 결정과 상충해 사용자 판단이 필요한 후보는 근거와 함께 확인받는다.

### Phase 4: 행동 검증과 이력 보존

1. 프로젝트의 기존 검증을 발견하고 구조·참조 일관성을 확인한다. 동일한 입력·런타임·모델·설정에서 기존 하네스와 후보를 비교하고, 관련 성공·실패 및 후보 작성에 쓰지 않은 사례의 행동을 확인한다.
2. 통합·참조 이동은 실제 로딩과 지시 준수를, 구성 발견은 정의의 이동·확장을 확인한다. description 변경은 적용 요청과 유사하지만 범위 밖인 요청으로 호출을 검증한다. 보호할 행동의 회귀는 원상복구하고, 필수 검증 미실행·불확실한 결과는 채택을 보류한다. 통과한 같은 검증은 조건이 달라지지 않으면 반복하지 않는다.
3. 과거 결정은 현재 지침과 분리해 기존 기록 위치에 보존한다. 위치가 없으면 프로젝트의 산출물 보관 관례를 따른다. 누락 없이 옮기고 도입 이유·상충 조사 시 읽는 포인터를 남긴다. 현재 지침에 실행 이력을 계속 덧붙이지 않는다.

### Phase 5: 결과와 성장 판정 보고

검토 범위, 조치·근거·보류, 검증 결과와 미평가 행동을 보고한다. 활성 지침 전체 크기, 대표 실행의 실제 로딩량, 기록 크기와 정리·평가 비용을 전후로 구분한다. 미계측은 미계측으로 남긴다.

기본 목표는 불필요한 내용 감소와 활성 지침의 순증가 방지다. 새 필수 의미로 증가가 필요하면 기존 내용 정제로 해결할 수 없는 이유와 검증 결과를 보고한다. 파일 분할은 전체 내용 감소로, 이력 이동은 전체 저장량 감소로 세지 않는다. 실행의 측정값·산출물 위치는 시점과 근거를 붙인 기록으로 남기고 지침의 고정값으로 재복제하지 않는다.

## 원칙

- 전체 하네스를 반복 요약하지 않고 근거가 있는 의미 단위만 고친다. 짧아져도 필요한 예외가 사라지면 개선이 아니다.
- 기록은 보존하되 현재 지침은 유효한 내용으로 유지한다. evolve 자신도 같은 검토 대상이다.
- 구성 추가·삭제나 팀 재설계가 필요하면 발견한 harness 구축 스킬로 연결한다. 정리를 이유로 검증 조건·자율 등급을 완화하지 않는다.
